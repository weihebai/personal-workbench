# 微信小程序备案监控实施计划

**目标：** 在工作台显示微信登录二维码，自动保存凭据，定时查询备案状态，变化及登录失效时通知。

**架构：** Go HTTP 客户端管理扫码会话和查询；复用现有凭据加密和 SMTP。新增独立监控表、接口及 React 页面，不修改现有业务接口。

**技术栈：** Go net/http、Gin、GORM、React、TanStack Query。

## 约束

- 前端仅做静态检查，不执行构建。
- 不输出或记录 Cookie 和 token；二维码及登录结果仅允许工作台已登录用户访问。
- 真实扫码确认由用户完成；不绕过微信验证。
- 未知状态和异常响应明确报错，不推测字段。

## 实施步骤

- [x] 添加微信客户端测试，覆盖扫码 Cookie 传递、登录 token 提取、备案状态、失效响应及异常字段；先确认失败，再实现客户端。
- [x] 添加监控接口测试，覆盖凭据隐藏、项目关联、状态变化、凭据失效及二维码过期；实现模型、接口和每小时检查。
- [x] 新增备案监控页面，提供创建监控、扫码、检查、暂停及移除；接入现有导航。
- [x] 真实微信服务二维码获取与图片格式验证通过，前端类型检查通过。
- [x] 最终 Go 全量测试、差异检查通过。

## 验证范围

真实扫码确认至凭据保存的完整流程，需要在更新后的工作台中人工扫码验证；自动测试覆盖其请求与状态处理。新增监控表允许旧备份缺表，恢复后监控为空。不同监控采用独立互斥锁，扫码会话表仅在读取或修改时短暂加锁。

## 验证重点

- 二维码过期后能重新生成；刷新页面不会暴露凭据。
- 重新扫码并发及定时检查不能覆盖新凭据。
- 登录失效与网络失败分别展示，网络失败保留上次备案状态。
- 失败的邮件发送允许下次重试，首次查询不发送状态变化通知。
- 非小程序账号和未知状态明确提示，缺失字段不当作未备案。
